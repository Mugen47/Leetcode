# 📝 15 - 3Sum

> [!NOTE]
> Link: [LeetCode 15](https://leetcode.com/problems/3sum/)
> Difficulty: Medium
> Pattern: Sorting + Two Pointers (Combination / Hidden Pattern)

### 1. Constraints
*   `3 <= nums.length <= 3000`
*   `-10^5 <= nums[i] <= 10^5`
*   Must not contain duplicate triplets.
*   Expected Time Complexity: $O(N^2)$ (because $N = 3000 \implies N^2 = 9 \times 10^6$, which easily passes, but $N^3$ would TLE).

### 2. First Thoughts
Finding three numbers that sum to a target in an unsorted array is incredibly difficult to do efficiently without using a hash map (which gets messy with duplicates). However, if we **sort** the array first, the problem suddenly simplifies. If we pick the first number manually and fix it in place, the problem reduces down to finding two numbers that sum to `-nums[i]` in a sorted array—which is exactly the Opposite Direction Two Pointers pattern we already mastered!

### 3. What Makes This Problem Difficult?
Handling the duplicates is the hardest part. Because the array can have `[-1, -1, 2]`, we must ensure we don't process the same fixed number twice, and we must ensure our left and right pointers don't process the same numbers twice when they find a valid triplet.

### Pattern Recognition
"Find 3 items that sum to X". The moment you see finding combinations in an unsorted array, think **Sort first, then Two Pointers**. 

### Hint 1
Fix the first element using a `for` loop. Now you need to find two elements in the remaining array that sum to `-fixed_element`.

### Hint 2
How do you handle duplicates? Since the array is sorted, identical numbers will be adjacent. If the current number is the same as the previous number, just `continue`.

<summary><b>💡 Core Insight</b></summary>
Sorting reduces the problem from an $O(N^3)$ nested-loop nightmare into an $O(N \log N)$ precomputation step followed by $N$ independent $O(N)$ Two Pointer searches. Total time: $O(N^2)$. Furthermore, sorting makes duplicate avoidance trivial because identical elements are guaranteed to be adjacent.

<details open>
<summary><b>💻 Implementation</b></summary>

```cpp
class Solution {
public:
    vector<vector<int>> threeSum(vector<int>& nums) {
        vector<vector<int>> result;
        int n = nums.size();

        // 1. Sort the array
        sort(nums.begin(), nums.end());
        
        for(int i = 0; i < n - 2; i++){
            // Optimization: If the smallest number is positive, we can never sum to 0
            if (nums[i] > 0) break;
            
            // Skip duplicate starting numbers
            if(i > 0 && nums[i] == nums[i - 1]) continue;
            
            int left = i + 1;
            int right = n - 1;
            
            while(left < right){
                int sum = nums[i] + nums[left] + nums[right];
                
                if(sum == 0){
                    result.push_back({nums[i], nums[left], nums[right]});
                    
                    left++;
                    right--;
                    
                    // Skip duplicates for the left and right pointers
                    while(left < right && nums[left] == nums[left - 1]) left++;
                    while(left < right && nums[right] == nums[right + 1]) right--;
                }
                else if(sum < 0) left++;
                else right--;
            }
        } 
        return result;
    }
};
```

</details>

<details>
<summary><b>🔍 Analysis & Edge Cases</b></summary>

### Correctness Proof
Sorting guarantees that we can use the Opposite Direction Two Pointers algorithm for the remaining two elements. Skipping adjacent duplicates guarantees that we never generate the same triplet twice, strictly fulfilling the requirement without needing an expensive `std::set`.

### Complexity
*   **Time:** $O(N^2)$ - Sorting takes $O(N \log N)$. The outer loop runs $N$ times. The inner Two Pointers loop runs at most $N$ times. Total time is $O(N \log N + N^2) = O(N^2)$.
*   **Space:** $O(1)$ or $O(\log N)$ depending on the internal sorting algorithm used by `std::sort`.

### Edge Cases
*   Array is all zeroes: `[0, 0, 0, 0]`. Triggers the `sum == 0` block, outputs `[0, 0, 0]`, then skips all remaining zeroes via the inner `while` loops.
*   Array elements are all positive: Triggers the `nums[i] > 0` break condition instantly.

</details>

### 🧠 What I Should Remember
**Sorting unlocks Two Pointers.** If a problem asks for combinations (sums, differences) and the array is unsorted, sorting it first is almost always the correct first step to reduce the time complexity by an entire power of $N$.
